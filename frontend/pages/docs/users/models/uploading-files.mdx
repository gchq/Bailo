# Uploading Files

Files represent any artefacts related to a model, such as binaries, configuration files, or supporting documentation.
These files allow others to build, evaluate, and use your model.

> **Common questions this page answers:**
>
> - How do I upload files to a model in Bailo?
> - How do I choose which folder my files are uploaded to?
> - What happens if a file of the same name already exists?
> - How do I attach files to a release?
> - How do I upload files programmatically?

## Adding files to a model

Upload files from the **File Management** tab on your model page:

1. Click **Add new files**
2. Set the **Destination folder**, or leave it empty to upload to the root
3. Click **Select files** to choose individual files, or **Select folder** to choose a whole folder
4. Optionally assign tags to each file using **Edit file tags**
5. Click **Upload files**

## Choosing where files are uploaded

Bailo organises a model's files into folders. A file's name includes its folder path, so a file named
`weights/model.bin` appears inside a `weights` folder in the file browser.

The **Destination folder** field controls where the files you are uploading will be placed:

- **Leave it empty** - the files are uploaded to the root of the model
- **Enter a path** - the files are uploaded into that folder, which is created if it does not already exist

When you open the upload dialog from inside a folder, the field is pre-filled with that folder's path. You can edit it
before uploading. The helper text beneath the field always confirms the destination.

A destination path must not start or end with a slash, must not contain double slashes, and must not contain empty
segments. If the path is not valid, the field shows an error and the upload is blocked until you correct it.

### Uploading a whole folder

When you use **Select folder**, Bailo keeps the folder's structure, including any sub-folders. The selected folder is
added beneath the destination folder you set. For example, selecting a folder named `sort-test` while the destination
folder is `test-upload` uploads a file at `zebra/z-file.txt` inside it as `test-upload/sort-test/zebra/z-file.txt`.

Each row in the Files to upload list shows the full path the file will be uploaded to, so you can check the structure
before you upload. Remove a file from the list using the cross beside its path.

## Handling files that already exist

If any file you are uploading has the same path and name as a file already on the model, Bailo shows a conflict step
before uploading anything. The conflict step lists each affected file with its existing and new size, and asks you to
choose what to do.

For each file you can choose one of two actions:

- **Skip** - leave the existing file untouched and do not upload the new one
- **Keep both** - upload the new file alongside the existing one, so the model has two files with the same name

Every conflict defaults to **Skip**, so nothing is uploaded unless you choose to upload it. You can also use **Keep Both
for All** or **Skip All** to apply one action to every conflict at once.

Files that do not conflict are uploaded normally, whichever action you choose for the ones that do.

### Files used by a release

Uploading a file never changes an existing file or the releases that use it. If you keep both, any release that uses the
existing file continues to use it, and the new file is not added to those releases.

To use the new file in a release, edit the release and select it. A release cannot contain two files with the same name,
so the new file replaces the existing one on that release. When you no longer need the existing file, delete it from the
Files tab. The deletion dialog lists any releases still using it.

## Adding files to a new release

When creating a new release, you can attach files in two ways:

- **Select existing files** - choose from files already uploaded to the model
- **Upload new files** - opens the upload dialog described above, and the uploaded files are added to the release
  automatically

## Uploading files programmatically

Use the Bailo Python Client to upload or download files via code. Pass `upload_name` to control the file's path on the
model, in the same way the Destination folder field does in the web interface:

```python
release.upload("model.bin", upload_name="weights/model.bin")
```

Without `upload_name`, the file is uploaded to the root of the model under its own file name.

The Python client does not check for conflicts. Uploading a name that already exists creates a second file with that
name, as **Keep both** does in the web interface, so check the model's existing files first if you are re-uploading.

Further examples are available [here](../../python/notebooks/models_and_releases_demo_pytorch.html).
